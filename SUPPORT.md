# Support

| What | Where |
|---|---|
| A bug | the form [Bug report](https://github.com/Lineward/lineward/issues/new?template=bug-report.yml) |
| A diagnostic that is wrong, or a problem it missed | the form [Diagnostic: false positive or missed problem](https://github.com/Lineward/lineward/issues/new?template=diagnostic.yml) |
| A question | [Discussions → Q&A](https://github.com/Lineward/lineward/discussions/categories/q-a) |
| A feature request | [Discussions → Ideas](https://github.com/Lineward/lineward/discussions/categories/ideas); it becomes an issue only once accepted onto a roadmap |
| A vulnerability | [private vulnerability reporting](https://github.com/Lineward/lineward/security/advisories/new), never a public issue ([`SECURITY.md`](SECURITY.md)) |
| A key that did not arrive | the website's lost-key page, <https://lineward.dev/lost-key>, or <sales@lineward.dev> |
| A refund, an invoice, a Team plan | <sales@lineward.dev>; a refund is carried out by Paddle |
| Personal data | <privacy@lineward.dev> |
| Someone's behaviour in the issues or Discussions | <conduct@lineward.dev>, as the [code of conduct](CODE_OF_CONDUCT.md) says |

Support is asynchronous and public, on a best-effort basis, with no SLA: there is no support e-mail, no Discord and no
Slack. Issues and Discussions are public, so never post a licence key, a payment detail, personal data or your own SQL
in them ([`CONTRIBUTING.md`](CONTRIBUTING.md)).
